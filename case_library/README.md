# 케이스 도서관 시제품 (윤석열 정부, 한국갤럽 데일리 오피니언)

> **데이터 이용 조건 주의**: 이 시제품은 비영리 연구용이다. 원자료 저작권은 한국갤럽에 있으며,
> 상업적으로 이용하기 전에는 반드시 한국갤럽과 이용 조건을 협의해야 한다.
> 원본 PDF는 `data/raw/`에만 두고 git에 올리지 않는다.

## 실행
```
pip install -r requirements.txt
python src/collect.py --limit 10   # 시험 수집
python src/collect.py              # 전체 수집
```

- `data/manifest.csv` : 대상 기간 호수별 수집 상태 + 보고서가 없는 주 목록(`no_report_this_week`)
- `data/robots_check.txt` : robots.txt 확인 기록
- `data/weekly.sqlite` : 파싱 결과 (테이블 survey, approval_by_group, reasons, party_by_group)
- `data/parse_failures.csv` : 검증에 실패해 DB에 넣지 않은 호수와 이유
- `data/parse_warnings.csv` : DB에는 넣었지만 확인해 둘 점(빈 칸, 이유 합계 반올림 등)

## 파싱 방식과 자동 검증
- PDF 숫자가 글자 단위로 흩어져 있어("1 ,001") 좌표로 다시 붙인다. 각 표의 '전체' 행 숫자 위치를 열 기준점으로 삼아 칸을 배정하므로, 빈 칸이 있어도 다른 열로 밀리지 않는다.
- 원본의 빈 칸은 NULL로 두고 `blank_cells`에 기록한다(0으로 채우지 않음). '-'(50사례 미만 미제시)는 NULL + `suppressed=1`.
- 자동 검증(하나라도 틀리면 그 호수는 DB에 넣지 않고 parse_failures.csv 에 기록):
  - 조사 개요 표본 수 = 직무 평가 표 '전체' 사례수 = 정당 표 '전체' 사례수
  - 권역·성·연령·직업 하위 집단 사례수 합 = 전체
  - 직무 평가 각 행 4개 비율 합 98~102%, 정당 지지도 각 행(무당층 세부 제외) 합 98~102%
  - 8개 집단 구분이 모두 있는지
  - 평가 이유 합계: 20~30개 항목을 각각 반올림해 싣기 때문에 98~102%를 벗어나는 호수가 실제로 있다(제502호 부정 이유 합 104%, 원본 확인).
    그래서 98~102% 밖은 경고, 95~106% 밖은 실패로 둔다.

## 3단계 사건 타임라인
```
python src/events.py
```
- 원문: 각 호수 게시물 본문(1단계에서 캐시한 `data/raw/html/content_*.html`, 새로 내려받지 않음)
  - '주요 사건' 목록: 갤럽이 정리한 그 주의 날짜별 사건. 한 줄에 '/'로 이어진 여러 사건을 하나씩 나눈다.
  - '조사 결과' 아래 대통령 직무 평가 해설 문단 → `data/weekly_commentary.csv` (검토할 때 참고, 5단계 케이스 카드에 사용)
- `data/events.csv` (1,545개 사건, 124개 호수): 사건 ID, 호수, 주, 조사 기간, 사건 날짜(날짜 없는 항목은 '주중 지속'),
  사건명, 원문 줄, 정책 분야(14개 고정 목록), 분야 후보, 관련 평가 이유, 출처 호수와 원문 URL
- 정책 분야와 관련 평가 이유는 **키워드 규칙으로 자동으로 붙인 값**이다.
  - 분야: 사건명에 들어 있는 분야별 키워드 수가 가장 많은 분야. 무작위 40개씩 두 번 직접 판정해 보니 약 75~80%가 적절했다.
    흔한 오류는 여러 분야에 걸친 사건(예: 의대 증원 입시 계획 → 교육/의료), 인물 중심 사건.
  - 관련 이유: 같은 호수의 긍정·부정 이유 중 같은 분야로 분류된 항목(증감 표시가 있거나 3% 이상)을 붙였다.
- 사람 검토: `review_events.html`을 브라우저로 열어 사건마다 승인·수정·삭제를 고르고 **검토 결과 CSV 저장**을 누른다.
  받은 `events_reviewed.csv`를 `data/`에 넣으면 5단계에서 '승인'·'수정' 사건만 쓴다.

## 4단계 기준선 모델
```
python src/baseline.py         # 기준선·잔차·조사 오차 → weekly.sqlite 의 baseline 테이블
python src/baseline_chart.py   # 확인용 그래프 → data/baseline_chart.html
```
- 결과와 모델 선택 이유: `data/baseline_report.md`, 후보별 수치: `data/baseline_model_comparison.csv`, 집단별: `data/baseline_group_eval.csv`
- baseline 테이블: 35개 집단(전체 + 직무 긍정률이 90% 이상 주에 있는 집단) × 112주.
  실제 긍정률, 기준선, 잔차, 비교용 로그 감소 기준선과 잔차, 직전 조사 대비 변화와 잔차 변화,
  표준오차(전체는 보고서 값, 없거나 집단이면 sqrt(p(1-p)/n) 계산값, `se_source`로 구분), 변화량 표준오차, 가장자리 표시(`edge`)

## 5단계 케이스 도서관
```
python src/cases.py   # cases.json, cases_summary.csv 를 만들고 검토 페이지(review_events.html)에 케이스 표시를 넣는다
```
- 감지 규칙(`config.yaml`의 `cases`):
  - 전체: 1~3번의 조사 사이 잔차 변화 > 1.96 × 변화량 표준오차 (95%)
  - 집단: 1~3번의 조사 사이 그 집단 잔차 변화 > 2 × 집단 표본오차(±1.96 × 표준오차)
  - 겹치는 신호는 한 케이스로 묶고, 끝 주는 기준 주에서 가장 멀리 벗어난 주(저점·고점)로 잡는다.
- 결과: 케이스 33개(전체 긍정률이 움직인 '전체' 22개, 일부 집단만 움직인 '집단' 11개)
- 카드 필드: 케이스 번호, 기준 주·시작 주·끝 주, 방향, 전체 변화량(실제·잔차·z), 집단별 변화량 순위(34개 집단),
  같은 기간 3%p 이상 늘거나 준 긍정·부정 이유(띄어쓰기만 다른 항목은 같은 항목으로 봄), 사건 후보(같은 주와 앞 주),
  회복에 걸린 주 수, 출처 호수 목록(게시물·PDF URL), 신뢰 수준과 그 근거, 갤럽 해설 발췌(300자 이내)
- 신뢰 수준: 이유 변화와 같은 분야로 분류된 사건이 1개면 '높음', 여러 개면 '낮음', 없으면 '판단 불가'.
  원인을 하나로 단정하지 않고 후보를 모두 남긴다. 사건 검토 전에는 '잠정'이다.
- 주의: 우연에 의한 신호도 섞여 있다. 전체는 약 330번(111주×3개 창)을 검사하므로 거짓 신호가 약 15개 기대되고(실제 66개),
  집단은 약 1만 번 검사해 거짓 신호가 약 60개 기대된다(실제 303개). 카드의 신뢰 수준 근거에 이 사실을 적었다.

## 6단계 역검증
```
python src/backtest.py   # data/backtest_results.csv, data/backtest_report.md
```
- 각 '전체' 케이스의 시작 주에 서서, 그보다 먼저 끝난 케이스 중 평가 이유 변화가 비슷한 3개로 다음 1·2주 집단별 변화를 예측.
  LOESS 기준선의 미래 정보 누설을 피하려고 잔차 대신 실제 긍정률 변화를 예측한다.
- 비교 기준: 변화 없음, 직전 추세 연장. 지표: 방향 적중률(잡음 범위 안은 '변화 없음'), 평균 절대오차, 범위 적중률.
- **결과: 유사 사례 예측은 '변화 없음'보다 못했다**(자세한 표는 `data/backtest_report.md` 첫 줄과 표).
  유사 사례 범위의 적중률(60%)도 같은 폭을 0 중심에 둔 범위(61%)와 차이가 없었다.
